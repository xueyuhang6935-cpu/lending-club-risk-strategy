输入沿原行号升序，与历史MySQL读取顺序一致；不是随机切分。主比例80%，已有辅助比例60%、70%、90%。风险升序，同分依次按SHA-256(`20261022:{loan_id}`)、贷款ID字符串升序。K=比例整数×N//100，不用浮点取整；标签不参与筛选。贷款ID不是已确认的借款人标识。

bootstrap使用固定模型分数，每年2000次贷款配对重抽样；每次三策略使用相同的N次有放回抽样，再分别按冻结排序重新保留K笔，重复贷款按权重处理。PCG64(SeedSequence([20261022, year]))，percentile 2.5%/97.5%线性分位点。候选减参照，负值代表候选保留人群核销比例更低。区间不覆盖训练不确定性、开发选择偏差、成熟度及未来环境变化，不控制借款人聚类，不保证多项同时覆盖。

## SQL

9份查询和schema原样保留，实际方言为SQLite 3，未声称已在MySQL验证。运行 `src/run.py` 自动从CSV重建标签、分组、策略决策，导入SQLite并依次执行01—09。03、04、06分别物化group_risk、group_contributions、loan_marks；其余直接查询。逐笔06和数据库只在忽略的outputs目录生成。

01/02读取已发布的上游状态汇总；03—05读取重新构造的用途×信用分90组；06—09使用重新训练产生的三策略保留标记。主键、外键及月份/标签对齐错误直接停止。信用分边界300/660/680/700/720/740/850，末档含850；15类用途含缺失，空组风险NULL而非0。新增组无法估计的反事实保持NULL。核销比例分母为保留数K，核销捕获率分母全部核销数，结清筛除率分母全部结清数；零分母NULL。

## 对账

`audit/verify.py` 按完整唯一键对照历史验收汇总，整数精确一致，浮点绝对容差1e-12，NULL位置一致；验证36行情景指标、9个bootstrap差值区间、8份汇总SQL及逐笔06的主键和各年等量保留数。

不同CPU或数值库可能产生数值差异；以实际verification.json为准，失败时不能声称精确重放。本次工程整理保留固定方法；重跑只为复现，未据新结果调整模型、特征、比例或结论。
